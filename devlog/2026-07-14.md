改用 `curl_cffi` 请求 DDG HTML 端点解决 TLS 问题，但 DDG 限流严重（bot detection + HTTP 202 anomaly page）。

### Bug Fixes (v0.6.1)

**Bug 1: Agent Loop 双重回答导致内容丢失**

- 根因：`agent_loop.py` Phase 1 中，`chat_with_tools()` 返回最终答案后，代码将其 append 到 messages 再 break。Phase 2 `chat_stream()` 看到 messages 中已有完整回答，只追加了一句"续集"式的收尾（如"以上为截至2026年1月的最新进展汇总。如需进一步了解..."），Phase 1 的完整答案被丢弃。
- 修复：不再将 Phase 1 的 `response["content"]` 追加到 messages。Phase 2 直接从 tool results 流式生成完整答案。

**Bug 2: HuggingFace SSL 错误（macOS LibreSSL）**

- 根因：`sentence-transformers` 每次加载 BGE-M3 时尝试从 huggingface.co 拉取 `modules.json` 检查更新。macOS LibreSSL 2.8.3 无法协商 TLS 1.3 → `SSLEOFError(8, 'EOF occurred in violation of protocol')`。
- 修复 Part A：`embedding_manager.py` 新增 `_is_model_cached()` 方法，检测模型是否已缓存（本地路径 + HF hub）。如已缓存，设置 `HF_HUB_OFFLINE=1` 跳过在线检查。
- 修复 Part B（模型本体未缓存时）：创建 `src/tools/download_bge_m3.py`，使用 macOS 系统 `curl`（SecureTransport，不依赖 LibreSSL）+ `hf-mirror.com` 镜像下载 BGE-M3（~2.3GB）到 `~/.cache/silicondreams/models/bge-m3/`。
- `embedding_manager.py` 新增 `_get_model_path()` 方法，优先使用本地缓存路径，完全避免触发 HuggingFace 网络请求。
- Python `requests`/`urllib3` 仍无法直连 huggingface.co（系统 LibreSSL 限制），但系统 `curl`（SecureTransport）和 `hf_transfer`（Rust/rustls）不受影响。
