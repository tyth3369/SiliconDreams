## v1.0.0-rc.3 deployable release artifact

- Added a tag-triggered GHCR workflow that publishes the exact release tag, smoke-tests the pushed digest through the real `/healthz` endpoint and generates a GitHub artifact provenance attestation.
- Added `compose.registry.yaml` so an ECS deployment can pull a fixed, prebuilt image while keeping the existing source-build workflow as a fallback.
- Updated the deployment guide with public/private GHCR package handling, immutable version selection, model initialization and image-based upgrades.
- Extended CI and architecture-policy tests to validate the registry Compose override and preserve the no-host-port boundary.
- GitHub Actions run `34775169826` published the public amd64 image, re-pulled its registry digest, passed the live `/healthz` smoke test and uploaded signed provenance to the registry and Rekor. Published digest: `sha256:d7cc625f0f5ded5367bc17002c289d5e9da2685444d66cb0ef1b708af164d2a3`.
- The first metadata run revealed that metadata-action's `latest=auto` flavor adds `latest` even when the explicit raw rule is disabled for a prerelease. Set `flavor: latest=false`; future prereleases publish only their version tag, while a stable tag may explicitly update `latest`.
