## v1.0.0-rc.2 dependency-security gate

- Audited the exported production environment with `pip-audit`. The only findings are five records representing four ChromaDB 1.5.9 advisories; upstream currently provides no patched version.
- Reviewed each advisory against the deployed architecture. The affected HTTP Server/RBAC/tenancy paths are not reachable because SiliconDreams uses only embedded `chromadb.PersistentClient`, defines no Chroma service, and exposes the application only to Caddy on the internal Docker network.
- Added `docs/security-advisories.md` with exact advisory links, scope, compensating controls, review date and mandatory removal conditions. This is a time-limited risk acceptance, not a claim that the dependency is fixed.
- Added `pip-audit` to the locked development toolchain and CI. Only the four reviewed IDs are ignored; any new finding fails the quality job.
- Increased the audit socket timeout from 15 to 60 seconds after a local PyPI read timeout; transient registry latency still fails closed rather than being treated as a clean audit.
- Added architecture-policy tests that reject `chromadb.HttpClient`, a Chroma server/service, or host port publication for the app container.
- Bumped the release candidate to v1.0.0-rc.2. Product behavior, UI and database schema remain unchanged from rc.1.
