# Dev Log — 2026-09-11

## Project takeover audit (Codex)

- Performed a read-only audit of the current FastAPI/HTMX UI, Agent loop, RAG pipeline, citations, financial data, dependencies, tests, and project documentation.
- Confirmed the current application is a useful proof of concept, but the documentation overstates several implemented capabilities.
- Highest-priority findings:
  - no Git repository and no executable tests (`pytest` collects 0 tests);
  - Python 3.9 is end-of-life and the installed environment fails `pip check` because of `grpcio` platform compatibility;
  - active chat path uses a duplicate calculator implementation instead of `src/tools/calculator.py`;
  - PDF sources are indexed under temporary filenames and page numbers are estimated instead of exact;
  - claimed BM25 / HyDE / Cross-encoder retrieval is not implemented;
  - citations enumerate retrieved sources, not claim-level supporting evidence;
  - global in-memory chat state is not durable or session-isolated;
  - unsanitized Markdown and manually assembled citation HTML create an XSS risk;
  - legacy LangChain/LlamaIndex code and dependencies remain despite being outside the active path;
  - terminology contains 100 entries, 102 dangling related-term edges, and known text defects.
- Recommended direction: retain the existing UI, rebuild the backend around typed evidence records, deterministic planning, exact-page ingestion, real hybrid retrieval, one canonical calculator, SQLite persistence, and evaluation gates.

## v0.7.0 PDF evidence and hybrid retrieval slice

- Reworked PDF parsing to consume PyMuPDF4LLM page chunks, preserving exact 1-indexed page provenance instead of estimating pages from character positions.
- Uploads now validate the real byte length and PDF magic signature, sanitize filenames, use SHA-256 content-addressed storage, and persist document ingestion status/errors in SQLite.
- Chunk IDs are deterministic; SQLite chunk IDs are reused as Chroma vector IDs so lexical and dense results refer to the same evidence record.
- Changed Chroma writes to idempotent upserts and configured cosine distance. Empty collections no longer initialize the 2.3 GB embedding model.
- Replaced the previous keyword-bonus pseudo-hybrid retrieval with actual BM25 scoring over persisted chunks, Chinese character n-gram tokenization, and weighted reciprocal-rank fusion with BGE-M3 dense retrieval.
- Added parser, exact-page provenance, deterministic ID, vector idempotency, Chinese BM25, RRF, PDF upload, and spoofed-file regression tests.
