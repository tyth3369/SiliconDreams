### Native Theme Integration (v0.3.0 — continued)

User identified a fundamental issue: `config.toml` static `primaryColor` doesn't switch between light/dark modes. Streamlit native components (radio, checkbox) show wrong accent color when theme changes.

**Solution discovered**: Streamlit **does** support `[theme.light]` and `[theme.dark]` subsections in config.toml for per-mode accent colors. This eliminates the need for custom JS theme detection entirely.

**Changes:**
- `.streamlit/config.toml` — Rewritten: `[theme.light]` (primaryColor=#003d80) + `[theme.dark]` (primaryColor=#ffb000). No static `[theme]` section.
- `styles/custom.css` — Major simplification: all colors derived from Streamlit native CSS variables (`--primary-color`, `--background-color`, `--text-color`) via `var()` + `color-mix()`. Removed `:root` color definitions, `:root[data-theme="light"]`, `@media` fallback. Down to ~320 lines.
- `app.py` — Removed entire JS theme injection (~30 lines), removed `"theme"` session state, removed sidebar theme radio + callback, removed `page_icon=""`, simplified `_inject_theme_css()` → `_inject_css()` (CSS only, no JS).
- `src/i18n.py` — Removed 4 theme keys: `theme.auto/light/dark`, `sidebar.settings_theme`.

**Architecture**: Single source of truth — Streamlit native theme. User selects theme via Settings (⋮) → Settings → Theme. "Use system setting" auto-detects OS preference. Radio/Checkbox/Button accent colors follow natively. CSS derives all colors from `--primary-color` etc. via `color-mix()`.

**Verification:**
- 15/15 modules OK
- Calculator precision OK
- Zero `data-theme` references in CSS
- Zero theme JS in app.py
- 46 CSS references to Streamlit native variables
- 2 keyframes only

### Streamlit → FastAPI + HTMX Migration (v0.4.0)

After multiple failed attempts to make Streamlit's theme system work correctly (`[theme.light]`/`[theme.dark]` subsections don't exist, JS injection stripped by sanitizer, Emotion CSS-in-JS overriding custom styles), user decided to abandon Streamlit entirely.

**New Architecture:**
- **Framework**: FastAPI + uvicorn (replaces Streamlit)
- **Templating**: Jinja2 (server-side HTML rendering)
- **Frontend**: HTMX (dynamic interactions) + pure HTML/CSS/JS (no framework)
- **Streaming**: SSE (Server-Sent Events) via `text/event-stream`
- **Theme**: CSS variables (`:root` dark default + `[data-theme="light"]` override), cookie-persisted, auto/dark/light
- **i18n**: Cookie-based language preference, no `st.session_state`

**Files Created:**
- `server.py` — FastAPI app (8 routes, SSE streaming, in-memory storage)
- `templates/index.html` — Main page (sidebar + chat + quick actions)
- `templates/components.html` — HTMX partials (sidebar_content, chat_response, kb_stats)
- `static/style.css` — Bloomberg Terminal theme (~370 lines, IBM Plex, pure CSS)
- `static/app.js` — Client JS (theme cookie, SSE streaming, language toggle, ~80 lines)

**Files Modified:**
- `src/i18n.py` — Removed `st.session_state` dependency; `get_i18n()` accepts `lang` parameter

**Backend preserved (14/15 modules zero changes):**
`llm_client`, `retriever`, `vector_store`, `pdf_parser`, `chunker`, `embedding_manager`, `agent`, `tools/*`, `terminology`, `report_generator`, `config`
